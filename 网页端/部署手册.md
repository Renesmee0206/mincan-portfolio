## 一、线上有两个站点，内容来源不一样（重点）

| 站点 | 地址 | 内容来源 | 更新方式 |
| --- | --- | --- | --- |
| GitHub Pages | `https://renesmee0206.github.io/mincan-portfolio/` | 仓库里的 `01-网站预览/` 整个文件夹 | push 到 `main` 后自动发布，约 30 秒 |
| 腾讯云开发 CloudBase 静态网站托管（国内，对外分享用这个） | `https://renesmee0206-d5gv71t4idf3cd3e2-1498270266.tcloudbaseapp.com` | 上传本地构建出来的 `02-网站源码/dist`（先跑 `npm run build`） | **手动**：去控制台把新的 `dist` 再传一次。push 到 `main` **不会**触发它 |

**这条必须记住**：两个站的更新方式是**分开**的——
GitHub Pages 发的是仓库里现成的 `01-网站预览/`（push 就自动发）；
腾讯云那个站发的是本地 `npm run build` 出来的 `dist/`，**要手动上传，仓库跟它没有任何联动**。
所以：改完源码 → ① `build-preview.mjs` 重出 `01-网站预览` → ② `npm run build` 出 `dist` 并上传 → ③ push。
漏掉②，腾讯云就永远停在旧版。

## 二、腾讯云开发 CloudBase 静态网站托管的配置

| 字段 | 值 |
| --- | --- |
| 平台 | 腾讯云开发 CloudBase → 静态网站托管（控制台 `console.cloud.tencent.com/tcb`） |
| 环境 ID | 待补（控制台左上角「环境 ID」；域名前缀里那串 `renesmee0206-d5gv71t4idf3cd3e2` 就是它） |
| 默认域名 | `https://renesmee0206-d5gv71t4idf3cd3e2-1498270266.tcloudbaseapp.com` |
| 上传内容 | `02-网站源码` 构建后的 `dist/`（`index.html` + `assets/` + `media/` + `favicon.png` + `resume.pdf`） |
| 更新方式 | 云开发控制台 → 静态网站托管 → 「上传文件」（把 `dist` 里的东西传上去）。**没有 Git 自动部署** |

本地出 `dist`：

```powershell

npm run build      # = vite build，产物在 dist/（约 79 个文件 / 65MB，大头是 3 个视频）
```

> **踩过的坑（2026-10-05）**：一直以为这个站跟 GitHub 联动、「push 完 1–3 分钟自动更新」，
> 其实**没有**配置任何自动化（仓库里 `.github/workflows/` 只有一个发 GitHub Pages 的；
> 本机也没装 CloudBase CLI、没有登录态）。结果 09-29 到 10-05 之间推不推代码，
> 线上都停在 09-29 那一次的构建：线上 `index.html` 还是 `width=1440` + `theme-color #141517` +
> 「视觉艺术设计」，而当前源码早就改成自适应 viewport + `#0e0e10` + 「AI 设计」了。
> **以后判断「腾讯云更新了没」就看这个**：拉一下线上 `index.html`，看 `viewport` 和引用的
> `assets/index-*.js` 哈希有没有变，别只看页面（CDN 有缓存）。
>
> 之前文档里写成「EdgeOne Pages」，是记录错误——EdgeOne Pages 的项目域名是 `*.edgeone.app`，
> 这里是 `*.tcloudbaseapp.com`，属于云开发 CloudBase 的静态托管。

**想让它以后自动更新**（可选，一次性配置）：用腾讯云官方的
`TencentCloudBase/cloudbase-action@v2`，在 GitHub 仓库加 `SECRET_ID` / `SECRET_KEY` / `ENV_ID`
三个 Secret（腾讯云 [访问管理](https://console.cloud.tencent.com/cam/capi) 建一对 API 密钥），
再让 Action 每次 push 后 `npm run build` + 部署到静态托管。密钥要你自己建、自己填。

### 二·五、从命令行部署（2026-10-05 起，Codex 可以直接做）

控制台那个「文件管理」得一个个点、还容易传错层级；命令行一条就能传完，
实测 74 个文件（65MB）约 20 秒。

**① 装 CLI**。这台机器上没有 npm，系统自带的 pnpm 因为 store 路径对不上用不了，
所以走 pnpm 独立版：

```powershell
# 下载 pnpm 独立版（约 41MB）并解压出 pnpm.exe：
#   https://github.com/pnpm/pnpm/releases/download/v11.25.0/pnpm-win32-x64.zip
# 注意：装包的目录要放在干净的临时目录（放 .codex-build 里会报 ERR_PNPM_UNEXPECTED_STORE）
#   先建一个 package.json： {"name":"tcb-local","private":true}
& "...\pnpm.exe" add "@cloudbase/cli"        # 装出来是 CloudBase CLI 3.8.x
```

**② 登录一次**（设备码流程：浏览器里点一下授权，不用把任何密钥给谁）：

```powershell
& .\node_modules\.bin\tcb.cmd login          # 会打印一个 tcb.cloud.tencent.com 授权链接
```

凭据落在 `C:\Users\Renesmee\.config\.cloudbase`，以后再部署不用重复登录。

**③ 部署**（传的是**打好的 `01-网站预览`**，跟 GitHub Pages 同一份，不是源码）：

```powershell
& .\node_modules\.bin\tcb.cmd hosting deploy "C:\Users\Renesmee\Desktop\闵灿作品集\01-网站预览" / -e renesmee0206-d5gv71t4idf3cd3e2 --safe
```

- `--safe`：发布前先备份，上传失败会自动回滚（备份在云端 `.cloudbase-backup/`，确认没问题后可删）
- 核对：`tcb hosting list /`，或者直接抓线上 `bundle.js` 跟本地比
- 控制台里的应用列表**不用管**——`tcb hosting deploy … /` 传的就是域名根目录那一份

## 三、GitHub Pages 的配置

- 发布文件：`.github/workflows/deploy.yml`（push 到 `main` 自动触发，也可以在 Actions 页面点 `Run workflow` 手动发布）
- 发布内容：仓库里的 `01-网站预览/` 文件夹（`upload-pages-artifact` → `deploy-pages`）
- 仓库设置：`Settings` → `Pages` → **Build and deployment** → `Source` 选 **GitHub Actions**

**踩过的坑（2026-09-29）**：第一次 Actions 运行失败，报：

```
Get Pages site failed. Please verify that the repository has Pages enabled and configured to build using GitHub Actions...
```

原因是仓库当时还没开启 Pages、来源也不是 GitHub Actions，所以后面的「上传 / 部署」两步根本没执行，线上一直是 404。
解决：按上面把 Source 设成 GitHub Actions，再点 `Re-run all jobs`（第二次 27 秒成功）。

## 四、日常更新怎么做

```powershell
cd C:\Users\Renesmee\Desktop\闵灿作品集

# 1) 改了源码就重新生成预览（只改说明文件 / 截图可以跳过这步）
node 02-网站源码\scripts\build-preview.mjs

# 2) 出腾讯云要的那份构建产物
cd 02-网站源码; npm run build; cd ..

# 3) 提交并推送 —— 这一步只更新 GitHub Pages
git add -A
git commit -m "更新：xxx"
git push      # 直连 GitHub 会被重置，用的是：git -c http.proxy=http://127.0.0.1:7897 push origin main

# 4) 腾讯云：控制台 → 静态网站托管 → 上传文件 → 选 02-网站源码\dist 里的内容
```

推完之后：

- GitHub：仓库 → `Actions`，看到绿色对勾（约 30 秒）
- 腾讯云：**不会自己动**，要按上面第 4 步手动传；传完在「文件管理」里能看到新上传时间和新的 `assets/index-*.js`
- 打开网址按 **Ctrl + F5** 强刷，避免浏览器拿旧缓存

### 改文字

只动 `02-网站源码/src/data/site.js`：项目、经历、奖项、联系方式全在这一个文件里。

### 换图片

把同名图片替换进 `02-网站源码/public/media/`，再跑一次 `build-preview.mjs`（脚本会把图片同步到 `01-网站预览/media/`）。
常用文件名：

| 用途 | 文件名 |
| --- | --- |
| 项目主图 | `p-01.webp` … `p-06.webp` |
| 项目细节图 | `d-01-1.webp` … `d-06-8.webp`（共 43 张，同时也是成果集锦的图片池） |
| 首页「What I like」 | `like-01-zima-blue.webp` … `like-07-theaters.webp`（源图在 `素材与原件/首页图片/`） |
| 成果集锦 | 不再单独一套素材，直接用上面的 `d-*`（前端每次随机抽一组） |
| 人物图 / 头像 | `portrait.webp` / `avatar.webp` |

> 换「What I like」的图时注意：这 7 张会在打包时**内联进 `bundle.js`**，
> 所以 `01-网站预览/media/` 里**看不到** `like-*.webp`，这是正常的，不是漏拷。

### 首页背景的极光

首屏背景那层慢慢转的极光是 **React Bits 的 Prism**（WebGL），代码在
`02-网站源码/src/components/Prism.jsx`，依赖 `ogl`（已在 `package.json` 里）。
两个站点都不用额外配置：GitHub Pages 发的是打好的 `01-网站预览`，
腾讯云现场 `npm install` 会把 `ogl` 装上。想调浓淡改 `global.css` 里 `.hero__prism` 的 `opacity`；
想关掉就把 `Hero.jsx` 里那段 `<Prism … />` 删掉。

### 换简历

替换 `02-网站源码/public/resume.pdf` 和 `01-网站预览/resume.pdf`（跑一次脚本会自动同步），两个文件要一致。

### 换视频

- GitHub 单文件上限 **100MB**，超了就推不上去；网站上现在两个视频是 **25.4MB / 21.1MB**（已经压过）。
- 新视频建议先压到 1080p / 3–4 Mbps（或 720p），单文件控制在 40MB 以内。
- **开场动画的视频**是单独一支：`02-网站源码/public/media/intro-open.mp4`
  （2.28MB，5 秒，**1112×834，4:3**，牛皮纸箱 + 深红底）。要换就同名替换这个文件，
  再跑一次 `build-preview.mjs`（脚本会自动同步到 `01-网站预览/media/`）。
  视频比屏幕窄时，空出来的地方**补成黑边**（`.intro__stage` 的底色 `#0b0b0d`，
  原来那条照素材取色的红色渐变换成了纯黑）。宽屏靠右贴边、竖屏铺满。
  那条黑边同时当**快递单**用（`.intro__from`：`FROM: MIN CAN.` +
  `Please claim your exclusive parcel.`），只在宽屏显示。
- 原片放 `素材与原件/原片备份/`，那里不会上传 GitHub。

## 六、让 Codex 代劳（可选）

可以直接说：「把首页第 3 张轮播图换成新的，然后推上去」或者「把联系方式里的电话改成 xxx，推上去」。
Codex 会：改文件 → 跑 `build-preview.mjs` → `git add/commit/push` → 告诉你等多久、记得强刷。

`.codex-build/site-check/shot.mjs` 驱动无头 Edge 自动生成，同样需要一次授权；生成后 `页面截图/`
会跟着更新。

## 七、出问题怎么查 / 怎么回退

- **GitHub 没更新**：仓库 → `Actions` 看有没有红色 ✗，点进去看报错原文。
- **腾讯云没更新**：先确认有没有人往控制台的「静态网站托管」传过新的 `dist`——这个站**不跟仓库联动**，
  没人传就永远是旧的（2026-10-05 就是踩了这个）。快速判断：浏览器打开
  `https://<域名>/index.html` 看源码，`viewport` 是不是 `width=device-width`、
  `assets/index-*.js` 的哈希跟本地 `dist/index.html` 里的一致不一致。
- **网页还是旧内容**：先 Ctrl + F5 强刷；腾讯云那边传完也要等一两分钟刷 CDN 缓存。
- **想退回上一版**：`git log --oneline` 找到目标提交，`git revert <commit>` 再 push，两个站点都会回到那一版。
